# WhatsApp Marketing Platform - Project Documentation

## 🚀 Overview
A comprehensive SaaS platform for WhatsApp Marketing and AI-integrated CRM, built with a modern TypeScript stack. It enables businesses to manage WhatsApp communications at scale using the Meta Graph API.

## 🛠 Tech Stack
- **Frontend:** React (TypeScript), Vite, TailwindCSS, Radix UI, TanStack Query.
- **Backend:** Node.js, Express, Socket.io (Real-time updates).
- **Database:** PostgreSQL with **Drizzle ORM** for type-safe queries.
- **Queue/Tasks:** BullMQ (powered by Redis, with DB-polling fallback).
- **Storage:** Local storage with DigitalOcean Spaces integration.

## 💻 Local Development Setup

### 1. Prerequisites
- **Node.js:** v20+ recommended.
- **PostgreSQL:** Running instance with a database named `diploy`.
- **Redis:** (Optional) If not available, the app falls back to in-memory/DB-polling.

### 2. Installation
```bash
npm install
```

### 3. Environment Configuration
Create a `.env` file based on `.env.example`.
Key variables:
- `DATABASE_URL`: `postgresql://user:pass@localhost:5432/diploy`
- `PORT`: `5001` (Default)
- `WHATSAPP_API_VERSION`: `v24.0`

### 4. Database Setup
```bash
# Push schema to database
npm run db:push

# Seed default users and configuration
npm run seed
```

### 5. Running the App
```bash
npm run dev
```
The app will be available at [http://localhost:5001](http://localhost:5001).

## 🏗 Project Structure
- `/client`: Frontend React application.
- `/server`: Express backend, controllers, and services.
- `/shared`: Shared Zod schemas and TypeScript types.
- `/packages/diploy-core`: Core internal library for logging, formatting, and constants.
- `/migrations`: Database migration files generated by Drizzle.

## 🛡 Security Audit Summary (June 2026)
A comprehensive security audit was performed with the following results:
- **No Malicious Code:** No backdoors, obfuscated scripts, or unauthorized exfiltration patterns found.
- **Safe Auth:** Passwords are securely hashed with bcrypt. Session-based authentication is used.
- **Sanitized Uploads:** File uploads are restricted by MIME-type and isolated by user ID.
- **External Calls:** All external traffic is limited to Meta, Payment Gateways (Stripe/Razorpay), and legitimate branding domains.

## 📝 Troubleshooting Notes
- **Vite Source Map Errors:** If `lucide-react` causes "Unterminated string literal" errors during dev, it is currently excluded in `vite.config.ts` with `sourcemap: false`.
- **Redis Fallback:** The server is configured to stay stable if Redis is missing, automatically switching to DB-polling for campaign processing.
- **Vite Error Handling:** The custom Vite logger in `server/vite.ts` has been modified to NOT exit the process on non-fatal frontend errors.
